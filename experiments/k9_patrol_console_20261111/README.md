# K9 콘솔 도움 요청 판정 · 누운 자세 지속 · 관제자 알림 · 순찰 보고서 (2026-11-11)

## 개요

팀 순찰 관제 프로그램(K9 PATROL 콘솔)에 붙일 규칙 모듈 5개와 평가 코드입니다.
11/11에 팀에서 정한 방향("도움 요청은 핵심 단어로 잡고, 비슷하게 들린 말은 의심으로 표시, 반복되면 우선순위를 올린다")을 구현하고, 이어서 필요한 기능을 같은 방식으로 만들었습니다.

모든 모듈은 Python 표준 라이브러리만 쓰고, 콘솔 코드에 의존하지 않습니다. **아직 콘솔에 연결하지 않았습니다.** 연결 위치는 [`INTEGRATION.md`](INTEGRATION.md)에 정리했습니다.

| 모듈 | 하는 일 | LLM |
|---|---|---|
| `help_request.py` | STT 원문에서 도움 요청 / 도움 요청 의심 판정 | 사용 안 함 |
| `lying_tracker.py` | 프레임별 자세 판정을 이어서 "누운 자세 N초 지속" 판단 | 사용 안 함 |
| `alerts.py` | 위 두 결과를 관제자 알림(긴급 확인 / 확인 필요 / 참고)으로 변환 | 사용 안 함 |
| `review_priority.py` | 중요 장면 선정에서 규칙이 먼저 고르고, LLM은 추가만 하도록 병합 | LLM 결과를 받아 병합 |
| `patrol_report.py` | 순찰 한 번의 기록을 한 장 보고서로 정리 | 총평 한 문단만 (실패하면 규칙 문장) |

## 1. 도움 요청 판정 (`help_request.py`)

11/05에 "살려주세요"가 STT에서 "사랑해주세요"(4회), "눈 와주세요"(2회)로 저장됐습니다. 원문을 고치지 않고 단계만 붙입니다.

| 단계 | 조건 | 예 |
|---|---|---|
| 도움 요청 | 원문에 도움 요청 표현이 그대로 있음 | 살려주세요, 도와줘, 사람 살려, 구해주세요, 119, 구급차 |
| 도움 요청 의심 | ① 자모 1개만 다르고 실제 단어가 아님 | 살려조세요, 도와주세오 |
| | ② 비슷한 말(유사도 0.70 이상)이 한 기록에서 2회 이상 반복 | 사랑해주세요 ×4 |
| 표시 안 함 | 비슷한 말이 1회뿐이거나, 어근만 같은 일상 표현 | 길 좀 알려주세요, 도와주셔서 감사합니다 |

**유사도만으로 의심을 붙이지 않은 이유.** 실제 오인식(0.75~0.89)과 "보여주세요" 같은 일상 부탁 표현(0.67~0.82)의 유사도가 겹칩니다([`eval/similarity_table.md`](eval/similarity_table.md)). "~주세요"로 끝나는 말은 대부분 비슷하게 나오기 때문입니다. 그래서 **반복**을 조건으로 넣었습니다. 일상 대화에서는 같은 짧은 부탁을 연달아 반복하는 일이 드뭅니다.

결과 ([`eval/keyword_eval_result.md`](eval/keyword_eval_result.md)):

| | 원문 그대로 일치만 볼 때 | 규칙: 도움 요청 | 규칙: 의심 | 표시 안 함 |
|---|---|---|---|---|
| 실제 도움 요청 발화 기록 3건 (11/02, 11/05) | 2 | 2 | 1 | 0 |
| 일상 문장 38건 (직접 작성) | 0 | 0 | 4 | 34 |

- 놓쳤던 "사랑해주세요 ×4" 기록이 의심으로 표시됩니다.
- 일상 문장에서 의심으로 뜬 4건은 모두 "알려주세요 알려주세요"처럼 **같은 부탁을 반복한 문장**입니다. 지금 규칙의 알려진 오경보 유형이며, 의심 단계는 원본 음성을 들어 보라는 표시입니다.

## 2. 누운 자세 지속 (`lying_tracker.py`)

`posture_rules.classify_posture`는 프레임 한 장만 봅니다. 허리를 숙이거나 관절 추정이 흔들려도 한 프레임은 누움으로 나올 수 있어서, 사람 상자를 프레임 사이에 이어 붙여 **누운 자세가 15초(설정값) 이상 이어질 때만** 사건으로 냅니다.

- 판단 불가·탐지 누락은 2초까지 허용, 서 있음·앉아 있음이 1초 이상 이어지면 종료
- 구간 안에서 누움 프레임 비율이 60% 미만이면 내지 않음
- 로봇이 돌아 상자가 겹치지 않아도, 누운 사람이 한 명뿐이면 같은 사람으로 이음
- "누운 자세 지속 관측"까지만 말하고, 낙상·의식 상태는 판단하지 않음

## 3. 관제자 알림 (`alerts.py`)

| 단계 | 조건 |
|---|---|
| 긴급 확인 | 도움 요청 발화 / 누운 자세 지속 + 30초 안의 도움 요청·의심 발화 |
| 확인 필요 | 누운 자세 지속만 / 의심 발화가 반복(한 기록 3회 이상, 또는 60초 안에 2개 기록) |
| 참고 | 의심 발화 1건 |

같은 종류 알림은 30초 안에서는 하나로 합치고(횟수만 증가), 단계가 올라가면 기존 알림을 올립니다. 발화자를 알 수 없으므로 발화와 누운 사람을 "같은 시간대 관측"으로만 적습니다. 화면 표시 예시는 `demo/alert_demo.html`입니다.

## 4. 선정 규칙 우선 병합 (`review_priority.py`)

11/07에 선정 속도를 고치면서 선정 결과가 5건에서 2건으로 바뀌었습니다. 어느 쪽이 맞는지 정하려면 기준이 필요해서 두 가지를 만들었습니다.

- **규칙 점수**: 도움 요청 3, 의심 반복 2, 누워 있음 2, 의심 1회 1 (누움과 발화가 같은 기록이면 +1). 2점 이상은 항상 표시
- **병합**: 규칙이 고른 기록을 먼저 넣고 LLM이 고른 기록을 뒤에 추가. LLM은 규칙이 고른 기록을 뺄 수 없음
- **채점용 시나리오 10개** (`eval/selection_scenarios.json`): 필수 / 선정 금지 / 선택으로 정답 표시

이 기준으로 보면 11/07에 빠진 3건(앉아 있음·판단 불가)은 "선택"에 해당하고, 필수인 음성 2건은 유지됐습니다. **LLM 채점은 아직 실행하지 못했습니다** (Ollama가 있는 환경에서 `--mode llm` 실행 필요).

## 5. 순찰 보고서 (`patrol_report.py`)

시간, 건수, 확인이 필요한 기록 목록은 모두 규칙으로 계산합니다. LLM은 집계 결과만 받아 총평 한 문단을 쓰고, 집계에 없는 숫자나 "쓰러짐·의식" 같은 단정 표현이 있으면 버리고 규칙 문장으로 대체합니다. 로봇 위치를 받지 않으므로 위치는 "미수신"으로 적습니다.

## 한계

- 유사도 기준 0.70과 반복 2회는 실제 오인식 사례 2종에 맞춘 임시값입니다. 녹음이 늘면 다시 정해야 합니다.
- 도움 요청 표현 목록은 한국어 몇 가지뿐이고, 비명이나 신음처럼 말이 아닌 소리는 다루지 않습니다.
- 로봇 스피커로 안내 방송을 하게 되면, 그 음성이 STT에 들어가 도움 요청으로 잡히지 않게 제외해야 합니다.
- 누운 자세 추적은 사람 상자 겹침 기준이라, 여러 사람이 겹치거나 로봇이 빠르게 움직이면 끊길 수 있습니다.
