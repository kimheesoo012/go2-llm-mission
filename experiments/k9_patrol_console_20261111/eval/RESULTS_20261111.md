# 11/11 김희수 작업 결과 (도움 요청 판정 · 누운 자세 지속 · 알림 · 선정 병합 · 순찰 보고서)

브랜치 `heesoo/help-request-alerts` (로컬). 새 파일: `help_request.py`, `lying_tracker.py`, `alerts.py`, `review_priority.py`, `patrol_report.py`, `tests/`, `eval/` 일부, `demo/`.
바뀐 파일: `speech.py`, `vision.py`, `highlights.py`, `app.py`, `storage.py`, `static/index.html`. 추가 설치 없음(표준 라이브러리만 사용).

## 1. 도움 요청 판정 (`help_request.py` → `speech.py`)

STT가 끝나면 원문에 단계를 붙여 `metadata.help_request`에 저장한다. 원문은 고치지 않는다.

| 단계 | 조건 | 예 |
|---|---|---|
| 도움 요청 | 원문에 도움 요청 표현이 그대로 있음 | 살려주세요, 도와줘, 사람 살려, 구해주세요, 119, 구급차 |
| 도움 요청 의심 | 자모 1개만 다르고 실제 단어가 아님 | 살려조세요 |
| | 비슷한 말(유사도 0.70 이상)이 한 기록에서 2회 이상 반복 | 사랑해주세요 ×4 |
| 표시 안 함 | 비슷한 말 1회, 어근만 같은 일상 표현 | 길 좀 알려주세요, 도와주셔서 감사합니다 |

- 유사도만으로 의심을 붙이지 않은 이유: 실제 오인식(0.75~0.89)과 "보여주세요" 같은 일상 부탁(0.67~0.82)의 유사도가 겹친다 (`eval/similarity_table.md`). 그래서 반복을 조건으로 넣었다.
- 저장된 실제 음성 기록 2건(11/05) + 11/02 시험 녹음 1건: 원문 일치만 보면 2건, 규칙으로는 3건 모두 표시 (도움 요청 2, 의심 1).
- 직접 쓴 일상 문장 38건: 의심 4건. 모두 "알려주세요 알려주세요"처럼 같은 부탁을 반복한 문장 (`eval/keyword_eval_result.md`).
- 규칙이 생기기 전에 저장된 음성 기록은 목록을 읽을 때만 계산해서 보여 준다 (DB는 수정하지 않음).

## 2. 누운 자세 지속 (`lying_tracker.py` → `vision.py`)

`classify_posture`는 프레임 한 장만 본다. 사람 상자를 프레임 사이에 이어서, 누운 자세가 15초(환경변수 `K9_LYING_SECONDS`, 최소 3초) 이상 이어질 때 한 번만:
- `누운 자세 지속` 기록을 전후 영상과 함께 저장 (`metadata.lying_sustained`)
- 관제자 알림 발생

판단 불가·탐지 누락은 2초까지 허용, 서 있음·앉아 있음이 1초 이상 이어지면 종료, 구간 안 누움 프레임이 60% 미만이면 내지 않는다.
**Go2 영상에 누운 장면이 아직 없어 실제 영상으로는 확인하지 못했다.** 가상 프레임 열 테스트만 통과.

## 3. 관제자 알림 (`alerts.py` → `app.py`, `index.html`)

| 단계 | 조건 | 소리 |
|---|---|---|
| 긴급 확인 | 도움 요청 발화 / 누운 자세 지속 + 같은 시간대의 도움 요청·의심 발화 | 3회 |
| 확인 필요 | 누운 자세 지속만 / 의심 발화 반복(한 기록 3회 이상 또는 60초 안에 2개 기록) | 1회 |
| 참고 | 의심 발화 1건 | 없음 |

화면 맨 위에 표시되고 `확인`을 누를 때까지 남는다. 같은 종류는 30초 안에서 하나로 합친다. 발화자를 알 수 없으므로 "같은 시간대 관측 (발화자 미확인)"으로만 적는다.
API: `GET /api/status`에 `alerts` 추가, `POST /api/alerts/ack {id}`.

## 4. 중요 장면 선정: 규칙 우선 (`review_priority.py` → `highlights.py`)

- 규칙 점수 2점 이상(도움 요청, 의심 3회 이상 반복, 누워 있음 후보)은 LLM 결과와 관계없이 항상 선정. LLM은 이유를 쓰고 다른 기록을 추가할 수만 있다.
- LLM이 꺼져 있거나 출력이 거부돼도, 규칙이 고른 기록이 있으면 그것만으로 결과를 낸다 (화면에 LLM 실패 표시).
- 선정 카드에 `규칙 선정` / `규칙 선정 · LLM 설명` / `LLM 추가 선정` 표시.

저장된 실제 기록 25건으로 확인:

| | 선정 결과 |
|---|---|
| 11/05 수정 전 LLM (5건) | 음성 2건 + 앉아 있음 후보 2건 + 판단 불가 1건 |
| 11/07 수정 후 LLM (2건) | 음성 2건 |
| 규칙만 (LLM 없이) | 음성 2건 (살려주세요 기록, 사랑해주세요 ×4 기록) |

11/05에 추가로 뽑혔던 3건의 이유는 "앉아 있음으로 분류되어 의식 상태나 부상 여부를 확인해야 함"으로, 프롬프트가 금지한 추정이었다. 규칙 기준으로는 이 3건을 뽑을 근거가 없어서, 11/07의 2건이 기준에 맞는 결과로 보인다.
채점용 시나리오 10개(`eval/selection_scenarios.json`)를 만들었고 규칙 모드는 10/10. **실제 LLM 채점(`--mode llm`)은 아직 실행하지 못했다.**

## 5. 순찰 보고서 (`patrol_report.py` → `app.py`, `index.html`)

`검토 대기 장면`의 `순찰 보고서` 버튼. 기간·건수·확인이 필요한 기록 목록은 규칙으로 계산하고, LLM은 집계 결과만 받아 총평 한 문단을 쓴다. 집계에 없는 숫자나 낙상·의식 같은 단정 표현이 나오면 버리고 규칙 문장을 쓴다. 위치는 받지 않으므로 "미수신".
API: `POST /api/report {session, model, llm}`, 결과는 `GET /api/status`의 `report`.

## 한계

- 유사도 0.70과 반복 2회는 실제 오인식 2종에 맞춘 임시값. 같은 부탁을 반복하는 일상 대화는 의심으로 뜰 수 있다.
- 비명·신음처럼 말이 아닌 소리는 다루지 않는다.
- 안내 방송을 로봇 스피커로 틀면 그 소리가 STT에 들어갈 수 있다 (지금은 녹음 중 재생이 막혀 있음).
- 누운 자세 추적은 사람 상자 겹침 기준이라 여러 사람이 겹치거나 로봇이 빨리 움직이면 끊길 수 있다.
- 녹음이 수동이라 음성 알림은 녹음 종료 후 STT가 끝나야 뜬다.
