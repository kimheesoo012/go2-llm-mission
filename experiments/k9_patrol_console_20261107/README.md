# K9 콘솔 자세 판별 규칙 · LLM 중요 장면 선정 성능 개선 (2026-11-07)

## 개요

팀 순찰 관제 프로그램(K9 PATROL 콘솔)에서 확인된 두 가지 문제를 개선한 작업입니다.

1. Go2 카메라 영상에서 서 있거나 앉은 사람이 `unknown`(판단 불가)으로 많이 분류되는 문제
2. 로컬 LLM으로 중요 장면을 선정하는 데 약 10분이 걸리는 문제

콘솔 전체 코드는 팀 저장소에 있으며, 이 폴더에는 **제가 작성한 변경 사항(패치)과 평가 코드·결과**만 담았습니다. 녹음·영상·기록 DB 같은 원본 데이터는 포함하지 않았습니다.

## 1. 자세 판별 규칙 개선 (`posture_rules.py`)

Go2 카메라가 바닥에서 약 30cm 높이에 있어 가까운 사람의 머리·어깨가 화면 밖으로 잘리고, 앉은 사람은 책상에 상체가 가려지는 경우가 많았습니다. 기존 규칙은 양쪽 어깨와 골반이 모두 보여야 판단했기 때문에 이런 장면을 모두 `unknown`으로 처리했습니다.

- 골반은 보이지만 어깨가 보이지 않으면 **하체 관절만으로** 서 있음·앉음을 판별합니다.
- 기존 규칙의 기준값(무릎 155°, 무릎 55~140° 등)을 그대로 사용하고, 몸통 대신 허벅지에 적용했습니다.
- 누운 자세는 지금처럼 몸통 관절이 필요하며, 하체만으로는 누움을 판정하지 않습니다.
- 정답은 규칙을 바꾸기 전에 관절 표시 이미지를 직접 보고 기록했습니다 (`eval/labels.csv`).

## 2. LLM 중요 장면 선정 속도 개선 (`highlights.py`)

측정해 보니 처리 시간의 약 68%가 출력 생성이었고, 중간 단계에서 작성한 선정 이유가 최종 결과에 쓰이지 않고 버려지고 있었습니다.

- 긴 기록 ID를 `r1`, `r2` 같은 짧은 번호로 바꾸고, 근거를 `time`·`speech`·`person`·`pose` 키로 전달합니다 (입력 약 70% 감소).
- 40개 이하 기록은 한 번의 호출로 처리하고, 그보다 많으면 후보 선별 단계에서 ID만 출력합니다.
- 컨텍스트 크기를 8,192로 고정하고, 모델을 30분 동안 메모리에 유지합니다.
- 선정 기준 문구, 원본 기록 ID·근거 검증, 화면 표시 형식은 그대로 유지했습니다.

**확인이 필요한 점:** 선정 결과가 5개(음성 2 + 자세 기록 3)에서 2개(음성 2)로 바뀌었습니다. 근거가 약한 기록이 빠진 것으로 보이지만, 적절성은 팀 내에서 추가로 확인해야 합니다.

## 사용 방법

팀 저장소의 K9 콘솔 폴더 상위에서 패치를 적용합니다.

```bash
git am heesoo-standing-rule-llm-speed.patch
```

적용하면 `k9_patrol_console/eval/` 아래에 평가 코드가 함께 들어가며, 다음처럼 실행합니다.

```bash
cd k9_patrol_console
python eval/posture_eval.py                      # 자세 판별 평가
python eval/llm_bench.py --data <data 폴더 사본>   # 중요 장면 선정 시간 측정 (Ollama 실행 필요)
```

`llm_bench.py`는 선정 결과를 DB에 저장하므로 반드시 data 폴더의 **사본**을 지정해야 합니다.
