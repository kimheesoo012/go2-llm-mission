## 1. 서 있음 규칙 수정 (할 일 5)

### 원인
Go2 카메라가 바닥에서 약 30cm라 가까운 사람은 머리·어깨가 화면 위로 잘리고, 앉은 사람은 책상에 상체가 가려진다.
기존 규칙은 **양쪽 어깨와 양쪽 골반이 모두 보여야** 판단해서, 이런 장면을 전부 `판단 불가`로 처리했다.

### 수정
- 양쪽 골반은 보이는데 어깨가 안 보이면 **하체만으로** 판단 (`lower_body`)
  - 서 있음: 무릎 155° 이상 + 허벅지가 수직에서 30° 이내 + 발목이 골반보다 충분히 아래
  - 앉아 있음: 무릎 55~140° + 허벅지가 수직에서 55° 이상(수평에 가까움) + 발목이 골반 아래
  - 기존 규칙의 기준값을 그대로 쓰고, 몸통 대신 허벅지에 적용 (새 기준값을 사진에 맞춰 만든 것 아님)
- 누워 있음은 여전히 몸통선이 필요 (하체만으로는 누움 판정 안 함 → 누움 오탐이 늘지 않음)
- 어깨가 보이는 경우의 기존 판정은 그대로. 이유 문구에 `(하체 기준)` 표시, metrics에 `basis` 추가, method `coco17_rules_v2`
- macOS 한글 폰트 경로 추가 (영상 라벨 한글 표시용)

### 결과: 실제 Go2 프레임 (data/media 스냅샷 25장 + 저장 영상 1초 간격 → 162프레임, 사람 탐지 101프레임)
실제 자세는 규칙 수정 **전에** 관절 그림을 보고 직접 표시 (`eval/labels.csv`). 사진 단위 = 확신도 1순위 사람.

| 실제 자세 | 장수 | 수정 전 맞음 | 수정 후 맞음 | 수정 후 판단 불가 | 잘못 판정 |
|---|---|---|---|---|---|
| 서 있음 | 23 | 7 | **16** | 7 | 0 → 0 |
| 앉아 있음 | 73 | 49 | **69** | 4 | 0 → 0 |

- 바뀐 프레임은 모두 `판단 불가 → 정답`. 서 있음↔앉아 있음 오판정, 누움 오탐은 수정 전후 모두 0
- 남은 서 있음 판단 불가 7장: 골반까지 화면 밖(다리만 보임) 5장, 멀고 작은 사람 1장, 하체 조건 불충족 1장
- 사람이 탐지된 101프레임 중 평가에서 뺀 5프레임: 가까운 물체로 렌즈가 가려진 4프레임 + 화면 끝에 다리 한쪽만 걸친 1프레임 (자세를 판단할 사람이 안 보임). 수정 전후 모두 `판단 불가`

- 교차 확인: 11/02 사진 실험 91장(변형 포함)에 수정 전후 규칙 적용 → 누운 사람 판정은 그대로. 바뀐 9명은 모두 판단 불가 → 서 있음(화면 끝에 잘린 서 있는 사람)/앉아 있음(누운 사람 옆 쪼그린 사람)

## 2. LLM 중요 장면 선정 속도 (할 일 1)

### 원인 (측정)
같은 19개 기록(11/05 19:01 선정 때와 같은 범위), 맥북 M4, qwen3.5:4b:

| | LLM 호출 | 입력 토큰/호출 | 출력 토큰/호출 | 총 시간 |
|---|---|---|---|---|
| 수정 전 | 3회 (10개씩 2묶음 + 최종) | 약 1,900~2,050 | 370~410 | **154.1초** |
| 수정 후 | 1회 | 1,416 | 79 | **22.6초** |

- 수정 전 시간의 68%가 출력(선정 이유 작성). 묶음 단계에서 쓴 이유는 버려지는데도 매번 작성하고 있었음
- 팀장님 노트북(Windows·WSL 경유)에서 600초 → 같은 비율이면 약 90초 예상 (**미측정, 현장 확인 필요**)
- 25개 전체 기록: 18.4초(모델 로드된 상태), 같은 요청 반복 시 8.0초. 두 번 실행 결과 동일

### 수정 (`highlights.py`)
1. LLM 입력 압축: 32자리 기록 ID → `r1, r2…` 짧은 번호, 근거를 `time / speech / person / pose` 키로. 입력 7,099자 → 2,103자 (25개 기준)
2. 한 번에 40개까지 한 번의 호출로 처리. 40개를 넘으면 **후보 선별은 ID만** 출력(이유 안 씀) → 최종 후보만 이유 작성
3. `num_ctx` 16384 → 8192 고정, `keep_alive` 30분 (선정할 때마다 모델 다시 올리지 않게)
4. 선정 기준·금지 사항 문구는 그대로 유지. 서버의 원본 ID·근거 검증도 그대로(짧은 번호를 원래 ID로 바꿔서 검증)
5. 화면 카드·이전 선정 기록 표시 형식은 그대로 (실제 콘솔에서 선정·이전 기록 열기 확인)

### 선정 결과가 달라진 점 (중요)
- 수정 전 5개: 음성 2개 + `앉아 있음`·`판단 불가` 자세 기록 3개 ("의식 상태나 부상 여부를 확인해야 함")
- 수정 후 2개: 음성 2개만. 프롬프트의 "일상 기록은 억지로 선택하지 마라"에 더 가깝지만, **선정 동작이 바뀐 것**이므로 팀 확인 필요
- 이유 문장에 "의식 상실" 같은 표현이 여전히 나올 수 있음 (수정 전에도 있었음). 프롬프트 개선은 별도 과제
